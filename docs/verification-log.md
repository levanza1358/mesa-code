## 2026-10-12 07:13 (local time)

Chat switching no longer flashes the previous session under the new task's header for a frame.
`useConversationProjection` owns a stale-lease guard: when the pane's rendered `sessionId` does not
match the lease it still holds from the previous session, the hook returns the closed projection
(snapshot `null`) instead of the old session's snapshot, so the whole pane renders empty/connecting
together until the matching lease arrives. `SessionPane` passes `lease?.sessionId ?? sessionId`,
widens `sessionLeaseReady` to also be false while the lease has not caught up, and folds it into the
composer-disabled flag so the editor stays disabled for the entire switch.

  (`tsx --test`) — 155 pass, 0 fail (the new 2 tests pin the guard: a lease matching the rendered
